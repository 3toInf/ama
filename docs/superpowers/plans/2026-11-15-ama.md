# AMA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Deliver a loadable local Chrome workspace extension with durable resources and safe tab archiving.

**Architecture:** Pure state logic plus a serialized Chrome API controller. A Manifest V3 worker serves a native side panel with no build dependencies.

**Tech Stack:** JavaScript ESM, Chrome MV3, HTML/CSS, node:test, Python zipfile.

**Spec:** docs/superpowers/specs/2026-11-15-ama-design.md

## Global Constraints

- Chrome minimum 121; no runtime dependencies or server.
- Automatic archiving is off by default, 12 hours when enabled, checked every 5 minutes.
- Persist before closing, recheck active/pinned/audio/loading/incognito protections before automatic closure.
- JSON import merges; never overwrite existing state or enable automatic archiving.
- Operate in the user-selected directory. Git metadata was initially read-only; after the permission update on 2026-11-15, git init succeeded on main.

## Review Focus

- Storage failure or rapid concurrent actions must not lose links or close unsaved archives (tasks 1 and 2).
- Malicious URLs, markup, oversized imports and invalid structures must be rejected or rendered as text (tasks 1 and 3).
- Window, tab and group IDs may become stale; never reuse previous-session group IDs (task 2).
- A tab becoming active while archiving must stay open; restoration failure must keep its archive (task 2).
- Browser APIs may be unavailable in restricted pages or older versions; surface errors without silent success (tasks 2 and 3).
