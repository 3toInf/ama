# Arc sidebar visual refresh

The user requested a closer match to Arc's UI and recognizable website icons. Work on the existing `feat_style` branch; retain the current workspace, split, archive and palette behavior.

## Visual references

- [Arc sidebar screenshot](https://dannyspina.com/blog/arc_browser): continuous tinted surface, compact favicon rows, folders and saved links above a divider, New Tab row, spaces at the bottom.
- [Arc Spaces screenshots](https://tidbits.com/2023/05/01/arc-will-change-the-way-you-work-on-the-web/): each space has a distinct sidebar tint.
- [Chrome favicon documentation](https://developer.chrome.com/docs/extensions/how-to/ui/favicons): use the extension-local `_favicon` endpoint with the `favicon` permission.

## Implementation

1. Replace dashboard branding/cards with a compact search header, workspace title, saved links/folders, open tabs and a bottom workspace dock. Native Chrome pinned tabs appear as icon tiles; no new Favorites data model.
2. Add a shared favicon component using Chrome's cache, with a local SVG fallback for missing icons or non-web pages. Use actual page URLs in sidebar and palette; no external favicon service.
3. Use 16px website icons, single-line tab titles, hover/focus actions and a raised active tab. Match light/dark surfaces, folder icons, empty states, palette and dialogs.
4. Verify favicon URL safety and palette URL preservation, existing unit/browser/native suites, favicon loading in a real extension and visual layouts at narrow widths in light/dark themes. Review the completed diff and package the extension.

## Boundaries

Chrome owns its native tab strip, address bar and side-panel container. This change styles AMA's sidebar and command window. Existing saved links remain per-workspace resources; the icon tiles represent Chrome's already-pinned tabs.
