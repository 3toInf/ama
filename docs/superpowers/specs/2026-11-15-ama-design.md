# AMA Chrome 扩展首版设计

用户已明确要求初始化 Git 并开始开发自己的扩展，本次直接在空项目中实施，不再要求确认开发方式。采用 Chrome Manifest V3、原生 JavaScript、HTML/CSS；没有运行时依赖和服务端。完整分析见 https://chatgpt.com/space/page_820f3e5185b0819192636b6541f31869 。

首版交付可加载的 Chrome 扩展：侧栏工作区、固定资源与文件夹、跨标签与资源搜索、手动及定时归档、恢复、工作区快照、JSON 备份导出与合并导入。提供域名路由，将匹配的新页面放入指定工作区。快捷键打开侧栏搜索；链接右键可加入工作区或打开轻量弹窗。

工作区以当前窗口中的 Chrome 标签组实现。切换仅展开目标组、折叠本扩展管理的其他组，不关闭网页、不修改无关组。会话中的组 ID 只存在 storage.session；浏览器重启后工作区资源和快照仍在，但不凭过期 ID 自动接管已有组。未分组标签单独显示，用户可将其收入工作区。切换不隔离网站账号。窗口关闭后不会自动恢复整个浏览会话，用户可从快照重开。

持久状态以单个 version=1 对象写入 chrome.storage.local。所有读改写操作通过 service worker 队列串行执行。资源只允许 http/https URL；导入须限制文件大小、校验结构、去重合并，不替换现有数据，也不自动启用归档。页面标题和导入文本只作为文本渲染。

备份采用紧凑 JSON，文件和完整数据备份上限均为 2 MB，每次持久写入前检查字节数。同名工作区的非空快照也合并，按网址去重、保留已有标题、取较新的快照时间。合并后单个快照超过 500 个网址或总数据超限时，整次拒绝且不修改原数据。

自动归档默认关闭，默认闲置时间 12 小时。启用后每 5 分钟检查；跳过活跃、固定、播放音频、加载中、隐身以及访问时间未知的标签，只处理 http/https 页面。归档必须先持久保存 URL，再关闭标签，并在关闭前重查保护条件。手动归档也保护固定、音频、隐身标签。归档保存 URL，不保存表单和页面内存。关闭失败保留恢复记录。恢复成功才移除归档记录。

权限为 tabs、tabGroups、storage、sidePanel、alarms、contextMenus。不读取 cookies、密码或网页正文，不申请全站脚本权限。首版不实现 AI 服务、持久 CSS Boosts、网站内 Peek、账号隔离和任意多页分屏；这些在后续版本增加，README 明确列出。

架构：core.js 处理状态、URL、搜索、归档资格与导入校验；controller.js 处理 Chrome API 副作用和数据队列；background.js 绑定事件；panel.js 与 panel.css 提供中文响应式侧栏界面。以 Node 内置测试验证规则和控制器边界，并在可启动的临时 Chrome 中验证界面。Chrome 扩展最低版本 121。

方案选择：多个现成插件无法交付用户要求的自研代码；React/构建链对首版侧栏并非必要。选择无依赖原生扩展，加载 extension 目录即可使用。Git 元数据原先只读；2026-11-15 更新环境权限后，已成功初始化 main 分支。
